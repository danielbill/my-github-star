### github Trend 页面（首页）取数据逻辑

注意：app只在打开时，有机会触发爬虫程序！！

1、app打开后首先获取数据库数据，从github-trending表和user-star-repo表中获取cached_at最新数据, 因为页面默认取weekly，所以只取weekly的数据，即两个weekly清单。

2、如果数据库无数据 —— 
    1、调用爬虫程序，从github获取数据，分别从trending和登录用户的数据中获取三分清单，github trending weekly， github trending monthly， user starred repositories，分别入库。
    2、入库时，cached_at只存放精确到小时的时间 26-02-14 12:00:00，没有分钟和秒，强行禁止频繁爬取github数据。
    3、数据按view所需排序保存在内存中，供首页查询展示。

3、如果数据库有数据，比较是否过期 ——
    1、取github-trending数据的cached_at时间，和当前系统时间对比，如果在同一小时内，则继续使用数据库数据展示，否则触发2.1逻辑。

4、用户标星库的更新逻辑 —— 
    1、stars_since = 新查询到的stargazers_count - 老的 stargazers_count  
    2、stargazers_count = 新查询到的stargazers_count
    3、time_range = 系统时间 - cached_at ， 只取小时部分，单位为小时。 即多少小时，各标星库增长的多少星。
